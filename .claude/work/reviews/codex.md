1. **Cards 05–06 — Remote access is not actually prevented.** `Host` is attacker-controlled: a machine on the LAN can request Apache with `Host: localhost`, read the page/token, then call process-starting endpoints. The spec says the dashboard must never be reachable outside the PC. **Fix:** bind the dashboard virtual host to `127.0.0.1` and `::1`, reject non-loopback `REMOTE_ADDR` in the guard, and add an integration test using a real HTTP request—not only a fabricated server array.

2. **Cards 02, 06 — Credentials remain web-accessible outside this project’s `.htaccess`.** The credentials directory is `C:\xampp\htdocs\.credentials`, a sibling of `_kc-dashboard`; rules in `_kc-dashboard/.htaccess` cannot protect it. **Fix:** add an Apache-level `<Directory "C:/xampp/htdocs/.credentials">Require all denied</Directory>` configuration card, verify it with an HTTP 403 test, and preferably move credentials outside the document root.

3. **Card 31 — Reusing `dashboard-collect.py` violates the intended scope and does not provide the assumed output.** The script imports a Buffer bearer token, calls Buffer and GitHub, writes cache files into the KC project, and prints prose rather than a machine-readable GA4/GSC result. It therefore exposes extra credentials and creates unrelated side effects; `NumbersTest` could pass against a fake while production collection cannot parse anything. **Fix:** add a read-only `--kc-dashboard-json` mode that runs only GA4 and Search Console inspection, emits JSON on stdout, writes no cache files, never imports `_secrets.buffer`, and rejects `--index`; add a real fixture-process contract test.

4. **Cards 09, 26, 29 — Random fences do not prevent prompt injection.** The tests only prove that mail/news cannot syntactically close a delimiter; an LLM can still follow instructions inside the block. **Fix:** use a fixed system instruction that treats all supplied content as quoted evidence, require a strict output schema, strip/reject unexpected fields, minimize supplied content, and add adversarial tests where mail/news asks the model to reveal files, credentials, prompts, or run commands. Ensure untrusted content is never sent to `claude -p`.

5. **Cards 12, 14, 15 — Project validation has a time-of-check/time-of-use junction attack.** A folder can be replaced with a junction after `ProjectList` validates it but before `proc_open`/`wt.exe` uses it. The picker test only checks a static listing. **Fix:** immediately before every process launch, canonicalize the selected directory, recheck that its parent is exactly the canonical htdocs root, reject all reparse points in the path, and test replacement with a junction between selection and launch.

6. **Cards 11, 15, 31, 34 — `proc_open` safety is specified but not proven on Windows.** Fake runners asserting an argv array cannot show that PHP 8.2 does not invoke `cmd.exe`, quote arguments incorrectly, or execute metacharacters. **Fix:** centralize process execution in one hardened `ProcessRunner`, accept only absolute allowlisted executable paths, set `bypass_shell`, constrain environment variables, and add Windows integration tests using arguments containing spaces, quotes, `&`, `|`, `%`, and traversal strings.

7. **Card 28 — The IMAP transport omits essential TLS and credential protections.** An allowlisted fake command stream does not test certificate/hostname verification, connection timeouts, LOGIN quoting, literal handling, or redaction of server errors. Malicious credential characters could alter the protocol command. **Fix:** require TLS peer and hostname verification, bounded reads/timeouts, safe IMAP string/literal encoding, account-specific redaction, and tests for CRLF/quote injection, invalid certificates, oversized literals, and passwords echoed in exceptions.

8. **Cards 28–29 — Mail identity and MIME handling are underspecified.** A bare UID is only meaningful within an account, mailbox, and `UIDVALIDITY`; reconnects or UID reuse can skip or conflate mail. There is also no card for MIME decoding, multipart selection, transfer encodings, character sets, or body-size limits. **Fix:** key processed messages by account + mailbox + UIDVALIDITY + UID, implement bounded MIME extraction, and test multiple accounts, UIDVALIDITY changes, attachments, HTML-only mail, malformed MIME, and oversized bodies.

9. **Cards 21–23 — Feed ingestion lacks network and URL security controls.** XXE coverage alone does not address SSRF, redirects to private addresses, decompression/XML bombs, huge responses, slow servers, or `javascript:`/`data:` story links. Assigning an untrusted URL to an anchor remains exploitable even when labels use `textContent`. **Fix:** allow only HTTP(S), block loopback/private/link-local destinations after every DNS resolution and redirect, enforce response/time/decompression limits, sanitize displayed links, and use `rel="noopener noreferrer"`.

10. **Cards 05–06 and all API cards — Security is tested at helper level, not at deployed routing level.** A developer can forget to call the guard, Apache can ignore `.htaccess`, or rewrites can expose source/data while all current tests pass. **Fix:** add an Apache integration-test card that requests every page/API and protected directory, verifies foreign Host and non-loopback rejection, verifies every write endpoint rejects GET/missing token/bad Origin, and confirms no token or secret appears in error bodies.

11. **Card 05 — Host/Origin rules are ambiguous and incomplete.** The plan does not define normalization for case, trailing dots, ports, duplicate `Host` headers, forwarded headers, IPv6, or absolute-form requests. A naïve string comparison will either reject the legitimate dashboard or admit malformed variants. **Fix:** define canonical accepted origin/authority pairs, ignore proxy headers, reject duplicates and malformed authorities, and add test vectors for ports, case, trailing dots, IPv6, embedded credentials, and comma-separated values.

12. **Cards 05–06 — The install token has no explicit filesystem permission or leakage controls.** “Never logged” and an `.htaccess` deny do not prevent another local account from reading `data/token`, nor PHP/Apache error pages from exposing it. **Fix:** create the file atomically with restrictive Windows ACLs, disable directory listings and verbose production errors, exclude token headers from access/debug logs, and test that responses and logs never contain the token.

13. **Card 06 — `.htaccess` has an incomplete deny list and a weak done-test.** It omits `chrome-extension/`, migrations if routing changes, hidden files, SQLite journal/WAL files, dotfiles, and potentially newly added top-level directories. Parsing for the presence of textual deny rules can pass when Apache does not enforce them. **Fix:** expose only `public/` through an Apache alias/document root, deny everything else by default, disable indexes, and verify inaccessible paths through HTTP.

14. **Cards 07, 14, 32 — Worker dispatch and job registration are missing.** Card 07 supplies registered handlers, but no later card builds the production registry containing `AskHandler` and weekly-note work. Card 32 simultaneously says it queues a job and that the note is saved, without defining who consumes that job. **Fix:** add a worker-composition card before the first queued feature, register each concrete job type, and test enqueue → worker process → stored result end to end.

15. **Card 13 — Slow-backend fallback does not satisfy the spec.** The card returns the over-budget answer and only routes the *next* call to the fallback. That is not fallback “when one is … over a latency budget,” and an indefinitely hanging request needs a hard timeout. **Fix:** enforce per-backend connect/overall timeouts, discard an over-budget result when safe, attempt the next backend for the current job, and test current-call fallback with a controllable clock.

16. **Cards 08, 13, 34 — No component actively determines which backend is live.** Historical `Health` rows can report a backend as live long after it has stopped, and neither llama-server nor Ollama startup/readiness is planned. **Fix:** add bounded health probes and process/startup documentation or scheduled startup tasks, record freshness, show “unknown/down” for stale results, and test stale-state behavior.

17. **Cards 19–20 — The Clients feature is not covered by its done-tests.** Card 20 tests due-date ordering rather than the required client panel, CRM leads, phase, next milestone, blocker, and site/GA4/Search Console/billing/repo/folder links. The real dashboard also separates active projects from `_PIPELINE.md`, which the test does not validate. **Fix:** add fixture assertions for both sources, every required field and link kind, slug override merging, missing/duplicate slugs, and UI panel rendering.

18. **Cards 24–26 — Project-profile coverage does not match the spec.** The plan extracts only package names, versions, and hosts, but the keyword matcher expects provider concepts such as WHC, DigitalOcean, OVH, and Cloudflare without specifying how they enter profiles. It also does not test rebuilding every project nightly. **Fix:** define a profile schema containing packages, versions, domains, hosts/providers, and source provenance; test all htdocs projects, exclusions, duplicate packages, lock/version formats, and nightly replacement of stale profiles.

19. **Cards 26–27 — Required impact-tag output has no effective UI/API test.** The spec requires project, one of four kinds, and one line explaining why. Card 27 only tests saving a correction; it does not prove tags are returned or rendered, or that corrections are scoped to the original story/project/tag. **Fix:** add an impact-query endpoint/UI contract and tests for project, normalized kind, one-line reason, escaping, stable tag identity, and correction reuse by Card 26.

20. **Card 29 — Retention can pass without deleting old bodies globally.** The done-test mentions one body older than 30 days, but does not require a recurring purge across every account or ensure bodies are absent from job payloads, failures, logs, and prompt traces. **Fix:** add an explicit retention job/transaction, never persist bodies in queue payloads or logs, and test boundary times plus cleanup after failed summarization.

21. **Cards 30 and 33 — Sensitive local data lacks cache controls.** Mail subjects/senders/summaries and business analytics could remain in browser/proxy caches. **Fix:** send `Cache-Control: no-store`, `Pragma: no-cache`, a restrictive CSP, `X-Content-Type-Options: nosniff`, and `Referrer-Policy: no-referrer` on the page and APIs; add header-level integration tests.

22. **Card 35 — The update flag has no persistence or presentation path.** The test only proves comparison logic. No migration, API field, or UI card displays the update that the spec says should be flagged. **Fix:** store check time/current/latest identifiers and error state, expose them through the health API, render them in Card 34, and test stale and failed checks.

23. **Card 36 — Extras have no UI implementation and incomplete dependencies.** It creates only `public/api/extras.php`; there is no JS/CSS rendering due dates, SSL expiry, or loop status. SSL targets are also not clearly sourced from client links/profiles, and recursive loop scanning may follow junctions. **Fix:** add an Extras UI card, depend on Cards 19/24, use an allowlisted set of HTTP(S) client domains plus `mail.sembr.co`, reject reparse points, and test rendering and navigation.

24. **Cards 31–33 — Search Console behavior is mismatched.** The reused Python script performs URL Inspection, while “KC numbers” ordinarily implies performance metrics; the plan merely says “stored values” and can accept any fixture shape. Its optional `--index` mode is also a write operation explicitly outside scope. **Fix:** specify exact GA4 and Search Console metrics and periods, forbid `--index` in the wrapper, and assert the complete production JSON schema and read-only scopes.

25. **Card 37 — Scheduled-task tests can pass while jobs never run correctly.** Checking that filenames appear does not verify triggers, recurrence, working directory, quoting, current-user identity, overlap policy, or that the worker runs often enough to process Ask Claude promptly. **Fix:** assert each task’s interval and arguments, absolute PHP/script paths, working directory, non-overlap policy, current-user interactive context where needed, and execute generated commands in a dry-run integration test.

26. **Cards 04 and 15 — The ordering is stale and unnecessarily blocks implementation.** `docs/SPEC.md` already records that Apache runs as Rob and gives the absolute `claude.exe`; Card 04’s done-test could also pass on unrelated occurrences of “Apache runs” and “Python.” **Fix:** remove Card 04 or mark it satisfied, make Card 15 directly use the recorded decision, and replace substring checks with validation of the specific dated decision fields.

27. **Cards 02–39 — The plan omits the mandatory mutation evidence from `.claude/project.md`.** Nearly every card’s done-test only says the tests pass; none requires intentionally breaking the new behavior and recording which assertion fails. Features can therefore have vacuous tests that always pass. **Fix:** add a mutation-check deliverable to every implementer card, with at least one named mutation per security boundary and feature outcome, and make the coordinator reject cards without that evidence.

28. **Card 39 — Security review is too late and its done-test is non-enforceable.** `.claude/project.md` requires a security-auditor pass for every risky path, but the plan defers everything to one final card and does not name an audit-report file. “Names a test or files a card” can pass without remediation. **Fix:** add a security gate immediately after each risky card, store findings in a defined report, require all critical/high findings fixed before dependent cards proceed, and make Card 39 rerun deployed HTTP/process/IMAP tests rather than merely inventorying them.
