# Plan review (Fable), 2026-10-12

Checked against `docs/SPEC.md`, `.claude/project.md`, `CLAUDE.md`, the real `_DASHBOARD.md`, `_PIPELINE.md`, `dashboard-collect.py`, XAMPP's `php.ini` and `httpd.conf`, and the machine (PHP 8.2.12, RTX 5060 8 GB, `claude.exe` 249 MB native binary, `llm/models/Ternary-Bonsai-2-27B-PTQ1_0.gguf` 5.9 GB present, `gpt-oss:20b` pulled, root `htdocs/.htaccess` already 403s `.credentials` and `.git`).

1. **Cards 05, 06, 14. The "exact Origin" check protects nothing, because `http://localhost` is one origin shared by every folder under htdocs.** Origin is scheme, host and port; the path is not part of it. Sixty-odd other apps live at `http://localhost/...` (wordpress-demo, webalizer, client sites, the XAMPP dashboard). Any of them can `fetch('/_kc-dashboard/')`, read the token out of the `<meta>` tag, and POST to `ask.php` with a passing Origin, Host and token. One stored XSS in any locally served site, or one malicious WordPress plugin, becomes `claude -p` in a project whose `.claude/settings.local.json` already allows `Bash(*)`. Fix: give the dashboard its own origin. Add `Listen 8787` and a `<VirtualHost *:8787>` with `DocumentRoot "C:/xampp/htdocs/_kc-dashboard/public"` to `httpd-vhosts.conf`; the guard then requires `Host: localhost:8787` and `Origin: http://localhost:8787`; the extension targets that URL. This also makes `src/`, `data/`, `tests/`, `config/`, `llm/` unreachable without any `.htaccess` (item 16). Make it a Rob card before 06, and change the done-tests in 05, 06, 17 and 18 to the port form.

2. **Card 29. Storing mail bodies for 30 days is a leak surface the spec does not need.** Bodies carry 2FA codes, password-reset links, invoices and client details, and they would sit in plain SQLite inside the webroot. The spec only says nothing is kept past 30 days; summarising on fetch needs no storage at all. Fix: never write the body column. Keep UID, mailbox, sender, subject, date, kind and summary. The done-test becomes "the mail table has no body column and the digest row for a fixture message holds no substring of the fixture body longer than the subject".

3. **Card 11 and every card that uses `ProcessRunner` (15, 31, 34). PHP 8.2.12 is older than the 8.2.18 fix for the `proc_open` array-mode command injection on Windows (GHSA-pc52-254m-w9w7 and its 8.2.20 follow-up).** When the executable is a `.bat` or `.cmd`, CreateProcess hands the line to `cmd.exe` and the array escaping is wrong. The plan refuses shims only inside `ClaudeRunner`. Fix: the refusal lives in `ProcessRunner`: the first argv item must be an absolute path to an existing `.exe`, no PATH lookup, and `.bat`, `.cmd`, `.ps1` throw before `proc_open`. Test it in `ProcessRunnerTest`, not only through the claude fake. Card 15 has a second instance of the same bug: `wt.exe -d <path> claude` cannot work, since there is no `claude.exe` on PATH (only `claude`, `claude.cmd`, `claude.ps1` in `%APPDATA%\npm`); wt would fail to resolve it or, if given `claude.cmd`, go through `cmd.exe`. Pass the absolute `claude.exe` from the spec decision.

4. **Cards 03 and 08. Nothing starts `llama-server`, and the fallback cannot fit next to it.** No card launches `llm/fork/llama-server.exe` with the GGUF, picks a port, puts the `llm/cudart` DLLs on its PATH, or restarts it at logon; `config/llm.php` names a port that nothing listens on, so the `bulk` chain always falls to Ollama. The GPU has 8151 MiB. Bonsai is 5.9 GB on disk plus KV cache; `gpt-oss:20b` is 13 GB. They cannot be resident together, and gpt-oss alone cannot be, so the "fallback" runs mostly on CPU at a few tokens per second and will blow any budget that Bonsai meets. Fix: add a card for `bin/start-llama-server.ps1` (absolute paths, `-ngl 99`, `--port`, `-c` sized to leave headroom) registered as an at-logon task in card 37, with `config/llm.php` reading the same port. Replace the fallback with a model that fits in the leftover VRAM or on CPU at an acceptable budget (a 4 GB class model) or keep gpt-oss and set its budget from a measured CPU run, not from Bonsai's. Card 03's done-test is already half true today; rewrite it to "llama-server answers `/v1/models` on the configured port".

5. **Cards 32, 29, 13, 11. Untrusted text can reach `claude -p`, and the argv test forbids the flags that would contain it.** The weekly note sends "the stored numbers" to the `judgement` chain, and those numbers include Bugsink error titles (anyone hitting a client site can put arbitrary text in an exception message or a 404 path) and GA4 page paths. Card 29 does not say which chain the digest uses. Fix: card 32 passes every string from collectors through `Prompt` as data and runs `claude -p` with `cwd` set to an empty temp folder (no project settings, so no pre-approved tools) and `--disallowedTools Bash,Edit,Write,MultiEdit,NotebookEdit,WebFetch,WebSearch`. Card 13's test asserts the `bulk` chain never contains `claude`, and card 29 states it uses `bulk`. Card 11's done-test currently pins argv to "exactly the four expected items", which would make the safety flags a test failure; change it to "contains `-p`, `--output-format json`, contains no `--dangerously-skip-permissions` or `--permission-mode`, and the prompt appears in no argv item".

6. **Cards 37 and 38. The scheduler script as described will either flash a console every minute on Rob's desktop or not run at all.** A task registered to run only when the user is logged on (the default for `-Principal` with `-LogonType Interactive`) opens a visible `php.exe` console on every repetition; `php-win.exe` hides its own window but children such as `claude.exe` still open one, because the CLI SAPI does not set `CREATE_NO_WINDOW`. A task registered "whether logged on or not" without a stored password (`-LogonType S4U`) runs in session 0 with no window, the profile is loaded, and `claude` finds `%USERPROFILE%\.claude\.credentials.json` (confirmed present). Fix: all `bin/*.php` tasks use `-LogonType S4U`, `-MultipleInstances IgnoreNew` (the worker's time budget is checked between jobs, so one `claude -p` of ten minutes must not be killed by the next minute's start), and an explicit `-WorkingDirectory`. Window-showing work (card 15) stays on the Apache side, which the spec confirms runs in Rob's session. Card 38's done-test lists tasks only; add "run the worker task once with `Start-ScheduledTask` and a queued Ask Claude job reaches `done`".

7. **Card 06 (bootstrap). XAMPP's `php.ini` has `display_errors=On` and `zend.exception_ignore_args=Off`, so any uncaught exception in `public/api/*.php` prints a stack trace with argument values: the token in `hash_equals()`, the IMAP password in `ImapClient::login()`.** The same trace goes to `C:\xampp\php\logs\php_error_log`. Fix: `src/bootstrap.php` sets `display_errors=0`, `zend.exception_ignore_args=1`, `html_errors=0` and installs an exception handler that returns a JSON 500 with no message. Done-test: a page test that throws inside a guard and asserts the output contains neither the token nor a stack frame.

8. **Card 12. `is_link()` returns false for a junction on this PHP, so "skipping junctions" as written does nothing.** Checked on 8.2.12: a junction made with `New-Item -ItemType Junction` reports `is_link=false`; `realpath()` does resolve it to the target. Fix: the list keeps a name only when `realpath($root . DIRECTORY_SEPARATOR . $name)` equals `realpath($root) . DIRECTORY_SEPARATOR . $name` exactly (string compare, case-sensitive). The done-test creates a real junction in the temp root (PowerShell `New-Item -ItemType Junction`, no admin needed) pointing outside it and asserts it is absent from the listing and resolves to null.

9. **Card 01. SQLite with Apache, the worker, fetch-news, tag-impact and mail-digest all writing will throw "database is locked".** Nothing in the card sets a journal mode or a busy timeout. Fix: `Db` runs `PRAGMA journal_mode=WAL` and `PRAGMA busy_timeout=5000` on open; `DbTest` asserts both by reading them back.

10. **Card 31. `dashboard-collect.py` is not the clean GA4 source the plan treats it as.** It imports `_secrets.buffer` and calls Buffer's GraphQL API and `gh issue list` before it touches GA4, and it exits 1 when any one of its four sources fails, so a `ProcessRunner` that treats non-zero as failure stores nothing on a Buffer or GitHub hiccup (and `gh` under an S4U task cannot open the Windows credential store it keeps its token in). Its GSC part is URL Inspection verdicts for five pages, not clicks and impressions, so "Search Console numbers" in the spec will be five index statuses. Fix: run it with its exit code ignored and read `kingsburycreative/admin/cache/ga4.json` and `gsc.json` afterwards, treating a `_error` key per file as that source's error; the done-test feeds fixture cache files, not fake stdout. Tell Rob the GSC gap in the spec, or add a small `searchanalytics.query` call to a copy of the script under this repo's `bin/`.

11. **Cards 34 and 35, ordering and storage.** The update check (35) has no table to write to and no card displays its flag, and the health API (34) is built before it exists. Spec feature 8 says the strip flags an update. Fix: swap them, add `009_settings.sql` (a key/value table) that 35 writes `llm.update_available` and `llm.update_detail` into, and 34's done-test asserts the flag appears in `health.php` output.

12. **Card 36 has no migration either.** `check-ssl.php` runs on a schedule and `extras.php` reads results, but no table is listed, and `LoopStatus` must scan htdocs for `.claude/work/loop/`, which is a directory walk that needs the same dot-folder and junction rules as card 12. Fix: add the table to the settings migration from item 11, and have `LoopStatus` iterate `ProjectList` rather than its own `scandir`.

13. **Cards 28 and 02. An expired certificate on `mail.sembr.co` (spec, 2026-10-03) will make that mailbox's TLS handshake fail, and the easy "fix" is the one that must be forbidden.** Fix: card 28's done-test asserts the stream context has `verify_peer` and `verify_peer_name` true and that `ImapClient` has no option to turn them off; the digest records "certificate error" for that mailbox and continues with the others. Card 02 tells Rob to use the WHC server's canonical hostname (valid cert) or renew `mail.sembr.co` first. Both `openssl.cafile` and `curl.cainfo` are set in `php.ini`, so verification works once the hostname is right.

16. **Card 06. `HtaccessTest` is a string match that passes with a rule Apache would ignore, and `.git/` is not on the deny list.** Fix: if item 1 is taken, the `.htaccess` card shrinks to `Options -Indexes`. 17. **Card 05. The guard must read `HTTP_HOST`, and the test must prove it.** `SERVER_NAME` is Apache's `ServerName localhost:80` no matter what the client sent, so a guard that reads it passes a fake-array test that only sets `HTTP_HOST` and fails in production against rebinding. Fix: every rejection case in `RequestGuardTest` sets `SERVER_NAME => 'localhost'` alongside the hostile `HTTP_HOST`.

18. **Card 11. `proc_terminate` on timeout kills `claude.exe` and leaves whatever it spawned.** Fix: on timeout run `taskkill.exe /PID <pid> /T /F` through the same `ProcessRunner` (an `.exe`, so allowed), then `proc_close`. Test: `FakeProcessRunner` records the taskkill call.

19. **Cards 16 and 20. 22. **Card 13. Ollama loads a model on first call, which with `gpt-oss:20b` on this GPU is tens of seconds.** The first call after idle trips the budget, marks the backend down and starts the cooldown, so the chain reports "all down" on exactly the night it is needed. Fix: the router issues a warm-up call (`max_tokens: 1`) outside the budget when a backend's last success is older than Ollama's keep-alive, and `config/llm.php` sets `OLLAMA_KEEP_ALIVE` guidance for the start script from item 4.
